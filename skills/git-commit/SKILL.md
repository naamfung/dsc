# git-commit — 生成规范的 Git 提交

在生成 git 提交前，遵循以下步骤。

## 提交前检查

1. 查看 `git status` 与 `git diff`，理解改动内容。
2. 只提交与当前任务直接相关的文件，避免 `git add -A` 误带入敏感文件（如 `.env`、凭证）。
3. 不要为未请求的改动提交空提交；无改动则告知用户无需提交。

## 提交信息规范

- 单条提交聚焦一个功能/修复，便于回滚。
- 提交信息说明「为什么」而不是「做了什么」。
- 使用当前仓库的历史风格：短前缀（如 `feat:`、`fix:`）+ 简洁描述。
- 使用 heredoc 方式传参，例如：

```sh
git commit -m "$(cat <<'EOF'
feat: 提交信息描述
EOF
)"
```

## 完成标准

- `git status` 确认提交成功且工作区干净。
- 只有在用户明确要求时才 push；默认不推送。
